# Domain documentation

Layout: single-context.

- Read `CONTEXT.md` when domain terminology or boundaries matter.
- Read the relevant `docs/adr/` decision before changing architecture or deployment.
- Read `docs/spec/hero.md` for approved interaction requirements and `docs/spec/open-questions.md` for unresolved choices.
- Revise existing authoritative material instead of duplicating it.
- Update `CONTEXT.md` only when domain meaning changes.
- Add an ADR only for a consequential, hard-to-reverse architectural decision, including status, context, decision and consequences.
- Inspect source and configuration directly for discoverable implementation facts.
