# Issue tracker

GitHub Issues in this repository is the only issue tracker. Do not create parallel task lists in documents or external systems.

- One issue per independently verifiable unit of work.
- Record scope, observable acceptance criteria, blockers and verification plan.
- Incoming requests start as `needs-triage`; approved implementation tickets use `ready-for-agent` when ready.
- Work on an issue only after approval. Record progress, outcomes and blockers in concise, technically neutral issue comments.
- Reference the corresponding issue in each implementation PR.
- Close only after verification and accepted review.
- External PRs are not an incoming triage surface by default.
- All issue and PR text may become public. Apply the publication checks in `AGENTS.md`.
