# Ryze Hero: одно вступление перед контентом

Дата: 17 ноября 2026. Репозиторий: looksawful/ryze-challenge (PRIVATE), локальная папка D:\inwork\ryze-challenge, ветка main. Устройство: только Titan / Primary RDK.

## Утверждённое поведение

1. При первом открытии JavaScript-версии, если движение разрешено, отображается полноэкранная анимация без Hero, навигации и Cookies.
2. Оригинальные 118 фрагментов собираются в логотип. К моменту сборки начинают двигаться шесть медиа-карточек с фотографиями и видео, каждая постепенно проявляется через прозрачность.
3. При превращении логотипа в круг он уменьшается до нулевого масштаба и становится прозрачным за 0,72 секунды, без смещения 3D-камеры и карточек.
4. Последняя карточка покидает сцену. Только после этого iframe отправляет родителю проверяемое по origin/source сообщение ryze:intro-complete. Hero, навигация и Cookies появляются одним плавным переходом (~0,68 секунды).
5. Вступление однократное, автоматический повтор исходного цикла выключен. После завершения Canvas перестаёт потреблять непрерывную отрисовку.
6. В reduced-motion не запускаем Canvas; Hero появляется сразу. Без JavaScript основное содержимое и штатная навигация видимы через noscript. При ошибке WebGL используется SVG, а при неизвестном сбое 24-секундный аварийный ограничитель предотвращает бесконечно пустую страницу.

## Изменения

- public/ryze-canvas/src/main.js: уменьшение 3D-логотипа (коэффициент .73 → .55), alpha-fade на старте картинок/видео, 3D shrink/fade при circle, синхронизация события завершения после последней карточки, отключение loop, резервный SVG.
- public/ryze-canvas/index.html, assets/card-media, src, vendor: полный автономный Canvas и шесть локальных медиа, ранее подготовленные в локальной рабочей версии.
- src/features/site-shell/HeroMotionBackground.tsx: отдельный полноэкранный визуальный слой с reduced-motion, без блокирования взаимодействий.
- src/features/site-shell/HeroWithNavigation.tsx и .module.css: SSR-ready intro state, same-origin postMessage, защита от ранней фокусировки через inert, появление Hero+navigation после завершения, no-JS стиль.
- src/features/hero/Hero.module.css: прозрачный фон под Canvas без смещения существующей композиции.
- src/app/page.module.css: отдельная панель Cookies теперь следует тому же состоянию, вместо появления поверх вступления.

## Цифровая проверка на Titan Chrome

- 1440×900: первый кадр stage=playing, Hero opacity=0, nav inert=true, Cookies hidden. Круг начинает уменьшаться приблизительно на 6-й секунде и исчезает; Hero и Cookies становятся видимыми только при окончании движения шестой карточки (~8,8 с). После завершения orbitCycle=1, видимых карточек нет, повторного запуска не происходит.
- 390×844: одиночная активная вкладка, событие завершения и reveal после последней карточки (~8,7 с); iframe WebGL работает.
- 874×402: stage=playing при запуске, затем ready, все карточки завершены.
- Reduced Motion 1366×768: stage=ready, Hero opacity=1, iframe отсутствует.
- No JavaScript 1366×768: контент и навигация видны; нет зависания на чёрном вступлении.
- При параллельных браузерных целях другая вкладка могла выполняться медленнее; поэтому также выполнена отдельная проверка телефона в активной вкладке.
- node --check для Canvas JS, npm run typecheck, npm run build — PASS. Полный suite/CI и физический Safari не выполнялись в разрешённом экспресс-режиме.

## Ограничения

Вступление сознательно занимает длительность исходной Canvas-сцены, обычно около 9 секунд. В случае невозможности воспроизведения аварийный ограничитель показывает сайт после 24 секунд; это не считается успешным прохождением интро. Никаких публичных деплоев. Мокап P0 пользователя остаётся отложенным.
