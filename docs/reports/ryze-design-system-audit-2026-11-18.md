# RYZE · Глубокий аудит визуальной системы, дизайна и качества

Дата: 18 ноября 2026. Статус: исследование, без исправлений и плана внедрения.
Код: repository root, main, исходный HEAD 93f823b, приватный репозиторий looksawful/ryze-challenge.
Сборка: private Hero preview (Tailscale only); Storybook: private Storybook preview (Tailscale only) (обе ссылки доступны только через Tailscale).
Браузер: MacBook test device, macOS 15.3, Google Chrome + Puppeteer, отдельный аккаунт Remote Desktop Commander.
Доказательства: local Mac QA artifacts (not committed).
Метод: чтение кода и согласованных требований, 11 рендеров целого Hero, 16 рендеров Storybook, измерение DOM-геометрии, проверка CTA, no-JS и отдельных сценариев, дизайн-критика по принципам Impeccable/Better Design/ui-consistency. ## Вердикт

Художественная идея убедительнее степени завершённости. Чёрный фон, один яркий magenta, крупный Karrik, функциональный Micro Grotesk, рисованный Rizzie и компактная навигация образуют узнаваемый фирменный язык. Его следует сохранять, не заменяя универсальным SaaS-шаблоном. Проблема не в отсутствии визуального стиля, а в отсутствии стабильной системы пропорций и одинаково тщательно обработанных вариантов и состояний.

Субъективные оценки 0–10, не Lighthouse и не объективная проверка WCAG:
- Идентичность бренда / арт-дирекшн: 8/10.
- Композиция Hero при 390×844: 7/10.
- Композиция Hero при 1440×900: 7/10.
- Сквозная адаптивность / геометрическая дисциплина: 4/10.
- Типографическая дисциплина: 6/10.
- Функциональные состояния: 7/10.
- Storybook как надёжный источник истины: 4/10.
- Общая дизайнерская зрелость первого экрана: ориентировочно 6/10.

Это только первый экран интерактивного прототипа, а не весь продукт: отсутствие backend и остальных страниц соответствует docs/spec/hero.md и не считается неполадкой.

## Сохранить неизменными как принципы

1. Фон #030303, акцент #FF5AF1, в основном монохромная палитра. Не добавлять декоративные градиенты и массовые «премиальные» карточки ради вида.
2. Karrik Regular для H1 и крупных выразительных элементов, Micro Grotesk для UI, минимальное количество текстовых акцентов.
3. Цветовое разведение частей заголовка, выразительный масштаб H1, лаконичная заявка на Shopify AI.
4. Собственный персонаж Rizzie, а не стандартная 3D-иллюстрация; фирменные логотипы платформ рядом с пояснением.
5. Фиксированная компактная навигация, самостоятельная мобильная версия; CTA как действие, а не декоративный объект.
6. Progressive enhancement: статический контент, Reduced Motion, Lightweight и Full Motion должны оставаться функциональными.

## Findings (для обсуждения до решения об изменениях)

### P1 / RX-01 — Бренд теряет согласованную позицию при ultrawide
Факт: на 2400×1350 розовый логотип x=10px слева, тогда как в других desktop он справа сверху. В Hero.module.css находятся ДВА перекрывающихся media для >=2400px: первый около строки 228 ставит logo в колонки 10–13, второй около строки 246 переписывает на 1–4 с отрицательным margin-inline -290px. Такое ведение одного и того же роли делает результат случайным для зрителя. Доказательство hero-ultrawide-2400x1350.png. Критерий будущей приёмки: положение бренда последовательно на всех desktop.

### P1 / RX-02 — Duo Open разбивает путь чтения
Факт: 951×669 H1 сверху слева, integrations сверху справа, description по центру справа, mascot внизу слева, бренд около (599,415), lead внизу слева, CTA внизу справа. Разница по вертикали description→CTA 250px. Этот вариант похож на набор независимых панелей, а не первую страницу одного продукта. Доказательство hero-duo-open-951x669.png и Hero.module.css специальные media 359+, 581+, 802+. Критерий: восстановить последовательность H1→lead→description→CTA и понятные роли двух половин, сохранив специальную Duo-композицию.

### P1 / RX-03 — Непредсказуемый вертикальный ритм
Факт: 2px при 320, 4px при 480, 22px при 390, 227px при 768 и 519px при 2400 для одной и той же пары смысловых блоков. Это разные схемы grid/flex с зафиксированными строками и большим числом переопределений. Много пустого места не воспринимается как намеренный «дорогой воздух», если не объединяет смысловые роли. Доказательства render-metrics.json, hero-tablet-portrait-768x1024.png, hero-ultrawide-2400x1350.png. Критерий: размерная система определяет ритм, а не остаток высоты.

### P1 / RX-04 — HeroAction в Storybook не соответствует реальному CTA
Факт: isolated story design-system-components-heroaction--interactive показывает на 390 и 1440 белую надпись «Start For Free» на чёрном поле, без светло-серой пилюли сайта. Вычисленный background у summary transparent. В HeroAction.stories.tsx пример включает HeroAction в className .action, но не содержит родителя .hero, который требуется контекстным селекторам Hero.module.css (.hero .action summary). Доказательство storybook-390/1440-design-system-components-heroaction--interactive.png. Критерий: компонент в Stories визуально репрезентирует тот же компонент в сайтом Hero.

### P1 / RX-05 — Десктоп без JavaScript имеет неоформленную дополнительную навигацию
Факт: при отключении JS на 1440 вместе с основной чип-навигацией появляется лишняя строка «▸ Menu» вне её контейнера, нативная подробная часть; два автоматических клика по summary не раскрыли details, тогда как в мобильном 390 нативный Menu открылся и отобразил 18 ссылок. Причину несрабатывания desktop надо дополнительно изолировать; не выдавать за проверенный WCAG-дефект. Доказательство no-js-desktop.png, no-js-mobile-menu.png, no-js.json; источник SiteHeader.tsx / SiteHeader.module.css. Критерий: нативный desktop fallback единственный, визуально интегрирован и кликабелен.

### P2 / RX-06 — Нет наглядного доказательства самого AI-продукта
Факт: выше сгиба показаны только обещание, персонаж, платформенные логотипы и CTA. Никакого UI Ryze или объяснения, что конкретно сделает AI, до клика нет. Better Design check_comprehension (только текст) — PASS: 29 слов и одна CTA, оценка 10 секунд на объяснение. Это не доказательство понятности продукта и не требование делать другую страницу. Арт-директорская гипотеза: экран пока скорее выразительный бренд-постер, чем убедительная демонстрация дорогого AI SaaS. Критерий: посетитель понимает характер конкретного действия продукта без декора.

### P2 / RX-07 — Типографические роли и состояния не имеют единого контракта
В foundation.css заданы Karrik и Micro. В ui/Typography.module.css .lead имеет font-weight:600, но Hero.module.css .hero .lead переопределяет на 400 и иной line-height. В самих Storybook-примерах типографика не соответствует фактической композиции H1/lead/paragraph на сайте. Значения размеров смешивают px, rem, vw и набор clamp. Базовый foreground #F7F7F7, nav #FFFFFF и локальные белые оттенки расходятся с ранее обсуждавшимся системным B3B3B3. Не объявлять каждое отличие ошибкой, сначала согласовать семантические роли. Доказательства: foundation.css, Typography.module.css, Hero.module.css, соответствующие Storybook PNG.

### P2 / RX-08 — Нестабильный масштаб Rizzie и интеграций
В 1440 картинка персонажа очень мала относительно H1, на Duo существенно крупнее и оттягивает внимание, в 2400 нижний ряд выглядит независимой композицией. На разных размерах logos и пояснение «Plugs into any platform» меняют взаимную близость. Доказательство 11 PNG, стили Hero.module.css. Не отвергать оригинальные медиа и характер рисованного персонажа. Критерий: устойчивый относительный масштаб и связность нижнего блока.

### P2 / RX-09 — CTA-флоу функционален, но стилистически скачет
В 1440 idle серая пилюля около 270px превращается в inline форму порядка 930px ширины с вложенной белой пилюлей и чёрной кнопкой; Rizzie и интеграции скрываются. Мобильный drawer выглядит отдельным, более компактным визуальным организмом. При валидном домене появляется тёмная result-card с двумя действиями. Путь работает: empty → alert/aria-invalid, valid → demo result, close → возврат фокуса; JS ошибок нет. Доказательства flows.json, flow-mobile-open/result.png, flow-desktop-open/result.png. Критерий: сохранить непрерывную систему материалов, размеров и иерархии во всех состояниях.

### P2 / RX-10 — Storybook имеет охват, но не является единственным источником истины
Найдено 20 индексных записей: 18 story и 2 docs, на основе 11 *.stories.tsx. Проверено по скриншотам 8 story ID ×2 ширины (390/1440), все HTTP200 и pageerror0. Истории делятся на два корня Design System/* и RYZE/Foundations/*; фонды/типографика частично дублируются. Navigation.stories.tsx всё ещё утверждает «same Segoe UI font as Hero», хотя сайт уже на Micro Grotesk. Только Hero.stories.tsx содержит status:"review"; статусы остальных не централизованы. Состояния и роли компонентов представлены не в полноте, в т.ч. отсутствует достоверный изолированный HeroAction. Критерий: соответствие итоговой реализации, единая иерархия каталога и статусность, компонентные состояния/моды/устройства проверяемы.

### P2 / RX-11 — Конфликт уровней отделки между публичным UI и dev-оболочками
Rizzie Playground показывает голые системные gray buttons «Show response» / «Reset position» поверх Hero; типографические примеры Storybook на чёрной полоске в белом canvas. Cookie panel на основном сайте выглядит отдельной сервисной областью. Это не основание редизайна Hero, но показатель отсутствия единого языка для controls/states. Доказательства storybook-...-rizzie--playground.png, ...foundations--typography.png, hero-desktop-1440x900.png. Критерий: отделять инструменты разработчика от визуально авторитетных примеров продукта.

### P2 / RX-12 — Дизайн-токены слабо управляют реальным Hero
foundation.css содержит spacing 4,8,12,16,24,32,48px (rem), semantic colors. Hero.module.css 883 строки и 30 блоков @media, множество отдельных px размеров; HeroAction.module.css содержит около 21 hex-значения. Важно: количество литералов не доказывает ошибку, некоторые арт-настроенные значения нужны. Риск — разные компоненты и брейкпоинты живут собственной шкалой, нет карты согласованных исключений. Критерий: различать системные роли и художественно обусловленные исключения, а не механически менять все единицы.

### P3 / RX-13 — Изолированные типографические презентации Storybook визуально неоформлены
Foundations/typography в виде чёрного прямоугольника на белом холсте; RYZE/Foundation typography — чёрная полоса с H1 почти впритык. Технически шрифт виден, но это не премиальное представление ролей в живой композиции. Доказательства storybook-1440-design-system-foundations--typography.png и ...ryze-foundations-typography--playground.png.

## Подтверждённые сильные практики

- Первый экран разборчив, в тестовой выборке ни одна ширина не дала горизонтального scroll документа.
- H1 computed Karrik: 390≈48px, 1440≈96px; Micro Grotesk для UI. Прямое совпадение с недавно выбранной парой и размерным тестом.
- Реальный CTA: mobile drawer и desktop inline form; пустые данные → role alert и aria-invalid; валидный test.myshopify.com → честная demo response; close возвращает фокус.
- Десктоп MegaMenu hover исправлен в предыдущем QA (коммит 93f823b), и mobile drawer был проверен отдельно на 320/390/874/951.
- Mobile no-JS fallback имеет 18 раскрываемых ссылок, основной смысл/CTA видны без JS; маскот не показывается намеренно.
- По заданным в коде цветам основной muted #777A83 / #030303 ≈4.81:1, secondary #999BA4 / #030303≈7.44:1; это лишь математическая проверка пары, не сертификация доступности.
- Нет pageerror в записанных сценариях; SiteHeader/CTA используют семантические кнопки, aria-expanded/alert, dialog/focus management.

## Слепые зоны

Не измерены полевые CWV LCP/INP/CLS, Lighthouse, реальные мобильные Safari/Firefox, VoiceOver, все сочетания Storybook Controls, zoom200/400, локализации/RTL, маломощные GPU и вся временная шкала motion. В Full Motion сделан один кадр 1440 на ~6.5с, на нём анимированные интеграции находятся в переходной фазе: не выдавать краткоживущий particle blob за постоянный дефект.

No-JS desktop-меню требует отдельной проверки причины открытия; браузерная проверка дала closed после click, но корень не локализован. Сайт предназначен для приватного просмотра; внешний аудит URL и SEO не запускался.
